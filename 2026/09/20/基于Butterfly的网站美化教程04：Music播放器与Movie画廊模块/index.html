基于Butterfly的网站美化教程04：Music播放器与Movie画廊模块

发表于2026-09-20|更新于2026-10-20|技术学习
|浏览量:

前言

上一篇我们把顶部导航菜单里加进了两个独立页面：/music/ 和 /movies/。这篇就把两页对应的模块从零搭起来：

  • Music：全站底部常驻一个迷你悬浮播放器（原生 <audio>，不依赖 APlayer），配一个歌单页，点歌即切。
  • Movie：本站不放电影，改放画——一个印象派油画画廊，点击封面弹出高清原图 + 底部配文。

两个模块都是纯前端 + 静态 JSON / YAML，不引入任何第三方服务，数据驱动，加歌加画不用碰代码。

格式与转码（踩坑）

浏览器 <audio> 对 mp3（H.264 音频）兼容性最好，其次是 ogg/m4a。网上下的无损 FLAC 不能直接播放，需要先转 mp3：

  • -q:a 2 是可变码率质量参数（约 190kbps VBR），个人博客够用又省空间
  • 顺手用 -metadata 写入 title/artist，Win 资源管理器直接看得到
  • 机器上可能有好几份 ffmpeg（比如 B 站、剪映自带的那种精简版），用前先 ffmpeg -encoders | findstr lame 确认有没有 libmp3lame，否则转码直接报错

校验编码器：ffmpeg -hide_banner -encoders | findstr /i lame

2. 歌单数据 music.json

底层播放器和歌单页共用同一份 JSON。结构很简单：

  • url 是相对根路径的静态文件直链
  • cover 封面可省（没有则不显示，播放器是纯文字风格，不影响体验）
  • 顺序即播放顺序，前一首放最上面

手写容易出错，我写了个脚本自动生成：tools/build-playlist.js

用法：node tools/build-playlist.js。加歌流程 = 放 mp3 进 audio/ → 在 TRACKS 加一行 → 跑一下脚本。别手改 music.json，它有 _note 提示就是提醒你它会随时被脚本覆盖。

4. 加画流程（不碰代码）

  1. 原图丢进 source/img/art/

PJAX 踩坑提醒

本站开了 PJAX，自定义 JS 有两个容易翻车的点：

  1. 不想每页重跑的逻辑（播放器）：挂在 body 上 + 只初始化一次 → 翻页时完全不受影响。
  2. 每页都要清理的东西（大图查看器）：页面切换瞬间如果不收起，旧遮罩会穿到下一页。所以查看器要监听 PJAX 导航开始事件主动关闭：
  1. 如果翻页爆红 Pjax switch fail: DOM doesn't look the same ... og:description - new 1, old 0，说明主题的 PJAX 校验把文章独有元素（OG 标签）也算进对比了，去 themes/butterfly/layout/includes/third-party/pjax.pug 删掉那批 selector 即可（见本站上一篇修复）。

构建与部署

常见问题

问题 原因 & 解决
歌单页点歌没反应 window.GlobalPlayer 未就绪。歌单脚本要等 globalMusicReady 事件再渲染，或直接加 defer 保证顺序
刷新后从开头播 sessionStorage 被清或没存到。检查 mq_sess 是否写入，seek 要等 loadedmetadata
自动播放被浏览器拦 正常。播放器已静音兜底自动播放，用户点音量键解除静音即可继续
画廊不渲染 {% art_gallery %} 插件在 scripts/ 里，忘了 hexo generate 或写错 data 文件名（_data/art.yml）
弹窗不留 desc art.yml 该条没写 desc，查看器会自动隐藏信息条，不算 bug
图片 art-broken 占位 img 路径写错，检查 source/img/art/ 下文件名是否一致

总结

  • Music = 本地 mp3 + music.json + global-player.js（原生 audio，底部常驻，会话恢复）
  • Movie = art.yml + {% art_gallery %} 标签 + art-viewer.js（点开看大图与配文）
  • 两端都遵循数据驱动：加歌加画只需改 JSON/YAML 与丢文件，不碰代码
  • 自定义 JS 与 PJAX 的配合原则：挂 body 的常在、进出页的有 pjax:start 清理
