Hexo Butterfly 修复文章右侧目录栏消失与不跟随的问题

发表于2026-09-02|更新于2026-09-02|技术学习
|浏览量:

前言

用 Hexo + Butterfly 主题写文章时发现两个问题：

  1. 目录栏消失：文章很长时，右侧目录栏随着页面一起向上滚动，很快就离开视口消失，无法固定在文章右侧。
  2. 目录不跟随：即使目录栏固定住了，往下读文章时目录列表也不会自动滚动定位到当前章节。

查资料、试了很多方案（改 CSS、写 JS、改模板……）都不行，最后终于找到病根。本文把这个正确的修复方法记录成一篇教程，希望能帮到遇到同样问题的人。

本文基于 Butterfly 主题（本项目版本 5.5.5），修复只需要改一行 CSS。

症状复现

  • 文章 30000 多像素长
  • 右侧栏有：作者卡、公告卡、目录卡、最新文章卡
  • 滚动到中途，右侧栏整个滚出屏幕；即便固定住，目录也不跟着文章走

网上常见方案为什么不管用

先说几个弯路，帮你避免浪费时间：

方案 结果
写 CSS 调 top 值 治标不治本
写 JS 监听滚动动态 fixed/sticky 布局错乱
把 TOC 移出 sticky_layout 改模板 破坏原有布局
给 .layout 加 align-items: flex-start 禁止 aside 拉伸 无效，目录照样消失

最后一个方案很多人推荐，但它其实误导了我们：问题不在 flex 拉伸。

真正的病根：body 被设成了滚动容器

Butterfly 主题在全局样式里写了这样一句：

对应文件：themes/butterfly/source/css/_global/index.styl

为什么这一行会毁掉目录？因为 CSS 规范里：

position: sticky 的元素，是相对它最近的滚动祖先来定位的，而不是相对视口。

一旦 body 设置了非 visible 的 overflow（scroll / auto / hidden 都算），body 就会变成一个滚动容器。可是真正滚动页面的是 html（视口），body 自己根本不滚动。于是 sticky 目录被绑定在一个「从不滚动」的容器上，表现就是：永远不固定，随着文章一起滚出屏幕。

一句话总结：

overflow-y: scroll 写在了 body 上，sticky 就废了。

验证方法

想快速验证是不是这个原因？在页面里随便放一个 position: sticky; top: 20px 的裸元素：

配套知识：为什么不能禁止 aside 拉伸

网上给「aside 拉伸导致目录消失」的说法是错的。恰恰相反——aside 被拉伸到和文章一样高，正是让目录能全程固定而不消失的关键。

布局结构是这样的：

position: sticky 的作用范围被限制在它的包含块（也就是 #aside-content）内。当 aside 被拉伸到 31000px 高时，目录卡的 sticky 范围就覆盖整篇文章：

  • 阅读到中途：作者卡、公告卡（不参与 sticky）自然滚出视口
  • 目录卡开始「粘」在 top: 20px，全程不消失
  • main.js 内置的 scrollFnToDo（滚动监听）给当前章节加 .active 并自动滚动目录列表，实现「目录跟随文章」

所以保持默认布局、不要加 align-items: flex-start，才是对的。

目录不跟随？检查 .toc-content 是否还能滚动

如果目录固定了但列表不跟着走，八成是有人把 .toc-content 的滚动去掉了。

最终效果

在 1440×900 视口、31000px 长文的实测结果：

滚动位置 右侧栏状态
0 ~ 900px 作者卡、公告卡可见，目录卡在下方
~1200px 作者/公告卡滚出视口，目录卡完全展开并固定在 top: 20px
1200 ~ 31000px 目录激活项自动跟随：动态字符串SDS → IntSet → ZipList压缩列表 → ...
文章末尾 sticky 自然释放，随页面收尾

总结

  1. 病根是 body { overflow-y: scroll } 把 body 变成滚动容器，sticky 因此失效。
  2. 一行修复：body 的 overflow-y 改为 visible，滚动条改由 html 预留。
  3. 保持 aside 的 flex 拉伸，目录卡才能覆盖整篇文章全程固定。
  4. 别动 .toc-content 的滚动，它是「目录自动跟随」的前提。
