基于Butterfly的网站美化教程03：实现访客定位欢迎卡片

发表于2026-09-19|更新于2026-09-18|技术学习
|浏览量:

前言

打开别人的 Hexo Butterfly 博客，经常能在右侧栏看到一张欢迎卡片：「🎉 欢迎来自 江西省 赣州市 的小伙伴，晚上好～落霞与孤鹜齐飞……」每次刷新还能换一句不同的句子。

本篇就把这个功能从零实现，把踩过的坑也一并记录，免得你再走弯路。

效果预览

  • 首次打开：立刻显示时间问候（不空白），定位完成后自动替换为省份 + 专属文案
  • 每次刷新页面：同一省份的 3 句文案随机抽 1 句，不会撞款
  • 定位失败：显示「欢迎来自 远方 的小伙伴」兜底

实现原理

整个功能的核心思路只有三步，没有任何后端服务：

  1. 渲染时间问候（纯本地，不请求任何接口，先保证卡片不空白）
  2. 拉 IP 定位（浏览器并行请求 3 个免费接口，第一个成功就用谁）
  3. 查表输出文案（用定位结果去省份文案表里抽一句话，拼接到卡片）

全程纯前端，Hexo 生成静态文件时不会处理这段逻辑，访客打开页面后 JS 才运行。

IP 定位接口选型（踩坑记录）

这是整个实现里坑最多的一环。因为浏览器环境强制执行 CORS（跨域资源共享），所以命令行能用的接口，浏览器不一定能用。

我用 Node.js fetch（行为和浏览器一致，强制校验 CORS）逐一测试了 8 个免费接口，结果如下：

接口 浏览器可用？ 说明
myip.ipip.net ✅ CORS *，86-420ms，IPv6也能识别，主力
api.vore.top ⚠️ CORS *，但时好时坏，经常 8s 超时，备用
ip-api.com ⚠️ HTTP 正常，HTTPS 永远 403，留作无害兜底
whois.pconline.com.cn ❌ 无 CORS 头，浏览器直接拦截
ip.useragentinfo.com ❌ DNS 已死，域名无效
api.ip.sb ❌ HTTPS 返回 403
ipapi.co ❌ HTTPS 返回 403
baidubce ❌ 返回 404

关键教训： 不要用 curl 或 PowerShell 测 CORS 接口，它们不执行跨域校验。必须用和浏览器行为一致的 fetch + Origin 头测试。

省份文案表设计

为什么要简称转全称？

不同接口返回的省份名不一致：myip 返回「江西」（无省字），vore 返回「江西省」。所以需要一张 PROVINCE_ALIAS 把简称统一转成全称，再查文案表。

多句随机抽选

最初每省只写 1 句，刷新看到的永远一样。升级后每省 3 句，按「诗词名句 / 美食地标 / 文艺收尾」体例，每次访问随机抽 1 句：

省份 诗词 美食 文艺
江西省 落霞与孤鹜齐飞… 一罐瓦罐汤… 赣江晚风凉…
广东省 老板，来两斤福建人 叹一盅两件… 珠江水浩浩…
四川省 天府之国，巴适得很！ 蜀道早已不再难… 峨眉山月半轮秋…

验证与部署

浏览器记得 Ctrl+F5 硬刷新清缓存。

如果卡片还是显示「远方」，打开 DevTools → Network → 筛选 JS，查看 welcome.js 是否加载成功；再看 Console 有没有红色 CORS 报错。

常见问题

问题 原因 & 解决
卡片始终显示「远方」 域名缓存未刷新，Ctrl+F5；或接口全部超时，检查网络
省份显示「江西」而非「江西省」 PROVINCE_ALIAS 缺少对应简称映射，补上即可
国内访问 GitHub Pages 时接口超时 myip.ipip.net 在国内可用；如仍超时，可以考虑加一层反代
每次刷新句子都一样 确认 pickText 函数已加，且省份值是数组而非字符串

总结

  1. 四件套改动：Pug 模板 + CSS + welcome.js + inject 配置，无后端依赖
  2. 接口选型是核心坑：浏览器 CORS 校验严格，curl 能用不代表浏览器能用，用 Node fetch + Origin 测试
  3. 34 省 × 3 句 + 16 国 × 2 句的静态文案表，每次随机抽 1 句，兼顾丰富度与零成本
  4. 完整源码已部署在 Y3148y.github.io，可直接查看

如果想给文案表扩容（比如加城市级语句），只需往 PROVINCE_TEXT 里追加数组即可，代码逻辑完全不用改。
