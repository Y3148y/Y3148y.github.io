① Value 从标量变成 d_v 维向量 输出从标量变成向量

第③步（缩放）的必要性：q·k 是 d_k 项乘积之和，d_k 越大，点积的方差越大（量级约 √d_k × 单个分量量级）。分数一大，softmax 就会”饱和”——最大的那个接近 1、其余接近 0，梯度趋近于 0，训练几乎停摆。除以 √d_k 把方差拉回 1 附近，梯度稳定。

1.5 三个矩阵的职责分工

矩阵 形状 职责 一句话
Q (Lq, d_k) 我要找什么 提问
K (Lk, d_k) 我是什么、能被怎么匹配 索引

关键：K 的使命到”算相似度”就结束了，加权求和的原材料是 V。

第二部分　缩放点积注意力

约定形状（最常用）：[batch, seq_len, dim]

  • batch：一批几句话
  • seq_len：一句几个 token
  • d_k：单个 Q/K 向量的维度

2.1 获取 query 向量维度

取最后一维长度，即每个 query 向量的维度。

2.2 transpose(-2,-1) 与 .T 的区别

.T 会把所有维度反转。对 [batch, Lk, d_k] 用 .T 会得到 [d_k, Lk, batch]——batch 也被翻到后面去了，而且不同样本的数据会被混在一起，语义彻底错乱。

transpose(-2, -1) 只交换倒数第二维和倒数第一维：

多头注意力时张量还会多一个 head 维（[B, H, T, D_h]），-2/-1 这种相对索引写法照样只动最后两维，所以是通用写法。这就是它不能写成 .T 的原因。

2.3 matmul 的批量语义：中间维是「收缩维」

先看二维铁律：

  • 必须满足：A 的列数 N = B 的行数 N
  • 计算方式：A 的第 i 行 · B 的第 j 列，全部相加，放进 C[i,j]
  • N 是求和收缩维：沿着它做”乘加”，算完之后 N 这个维度直接消失

所以结果”是 M 和 P”，不是因为 M×P，而是：保留左边矩阵的行数、右边矩阵的列数，中间那一维被吃掉了。

升到三维：

前面的 B 完全不参与矩阵运算，它只是”分组标记”：

套进注意力：

符号 数值 含义
M = Lq 3 有几个 query（结果的行数）
N = d_k 5 向量长度（收缩维，算完消失）
P = Lk 4 有几个 key（结果的列数）

输出 [B, Lq, Lk]：每一行是一个 query，每一列是一个 key，格子里是这一对的相似度。

2.4 softmax 的 dim 参数选择

scores 形状 [batch, Lq, Lk]，最后一维是所有 key。softmax 必须沿着”我要在谁之间分配权重”的那一维做。

对某个 query（固定 m）而言，它要在所有 key（n 遍历）之间分配注意力，所以沿 Lk（最后一维）归一化。结果：同一行权重和为 1。

如果误写成 dim=-2，就变成”同一列（同一个 key）在不同 query 之间归一化”，语义完全错了。

2.5 dropout 的添加位置

加在注意力权重 p_attn 上，不是加在 Q/K/V 上。作用是随机让一部分注意力连接失效，逼模型不要依赖单一位置，抑制过拟合。推理时关闭。

2.6 返回注意力输出与权重矩阵

  • 第一个：[B, Lq, Lk] @ [B, Lk, d_v] = [B, Lq, d_v]，注意力输出
  • 第二个：p_attn 权重矩阵，用于可视化（看模型把注意力分给了哪些词）

第四部分　多头注意力：把 512 切成 8 份预算

4.1 隐藏维度的含义

args.dim = 512：每个 token 在模型内部被表示为一条 512 维向量。叫”隐藏”是因为它不是词表 ID，是模型内部看不见的表征。

句子 I love cat，每个 token 进注意力前都是一条 512 维向量：

4.2 方案 A vs 方案 B（真实方案）

dim=512, n_heads=8

方案 A（直觉但错的）：每个头都生成完整 512 维 Q/K/V

  • 8 个头 → wq 输出 8×512 = 4096
  • 参数量 ×8，显存爆炸，拼接后还要再降维
  • 原版 Transformer 不这么做

方案 B（真实）：总预算固定 512，8 个头瓜分

⚠️ 关键澄清两句：

  1. 各头之间规格是相等的：每个头的向量都是 64 维。
  2. 单个头的 QKV ≠ 模型隐藏维度：64 是”子空间维度”，8 个 64 拼起来才铺满 512。

⚠️ 另一个高频误解：wq 不是简单切割原向量。它是一个线性层，把原始 512 维表征映射到新的 512 维空间，这个新空间刚好能均分成 8 段：

画布比喻：一张 512 像素的画布，8 个画家（头）分工。原版方案把画布切成 8 块、每人 64 像素，画完拼回去仍是 512；方案 A 是给每人一张完整画布，总共 8 张，开销翻 8 倍。

4.3 view + transpose(1,2) 的作用

  • view：重塑，把最后一维拆成 (H, D_h) 两维，数据顺序不变
  • transpose(1,2)：交换序列长度和头两个维度

为什么必须换？因为单头注意力的输入格式是 [B, L, D]，matmul 只对最后两维做矩阵乘、前面所有维都当”批量”。

把 H 换到 batch 的位置后，对每个头 h，切出来的子张量正好是 [bsz, T, D_h]——完美适配单头注意力，H 变成了一个额外的批量维度，8 个头自动并行、互不干扰。

这就是”多头”能在一次 matmul 里跑完的全部秘密。

4.4 缩放因子应使用 head_dim

点积是在单个头的 64 维子空间里做的，所以缩放因子必须是 √64 = 8，而不是 √512。

4.5 因果 mask 的构造

  1. 先造全 -inf 矩阵，形状 [1, 1, maxL, maxL]
  2. torch.triu(..., diagonal=1)：保留对角线右上方（上三角）
    • mask[i,j] = -inf 表示第 i 个 token 不允许看第 j 个（未来）token
  3. 后面 scores + mask，-inf 进 softmax 直接变 0，权重消失
  4. register_buffer：不是可训练参数，是固定常量，跟着模型保存但不算梯度
  5. 前两个维度是 1 → 可广播到任意 batch、任意头数，省内存

4.6 拼接与输出投影

contiguous() 不能省：transpose 之后内存不连续，view 会报错（或需要先拷贝）。

wo 的作用：8 个头各算各的，彼此之间没有任何交流；wo 是一次线性混合，让不同头的信息可以相互作用。

4.7 全程 shape 流水

一行速记：投影 → 切开分头 → 换维度让头当 batch → 各头独立点积注意力 → 拼回 → wo 融合。

第五部分　MLP 与 Encoder / Decoder 层

5.1 Attention 找关系，MLP 加工特征

标准 Transformer MLP（FFN）：

最本质的区别：

多头注意力是让 token 互相看、交换信息；
MLP 完全不做 token 之间的交互——序列里每个 token 拿自己的向量，独立跑一遍，各算各的。

句子 I love cat：

  • 注意力阶段：cat 能看到 I、love
  • MLP 阶段：I、love、cat 三条向量分别进网络，互不通信

分工：Attention 负责”找关系”（谁和谁有关），MLP 负责”加工特征”（对找到的信息做非线性变换）。

5.2 Pre-LN 与残差连接结构

  • x + ...：残差连接，解决深层网络梯度消失，让梯度有一条”高速公路”直达浅层
  • attention_norm 放在 attn 前面 → Pre-LN（Llama 系列全是这个；原论文是 Post-LN）

5.3 DecoderLayer 结构

  • Masked Self-Attn：GPT 式，token 只能看自己和左边
  • Cross-Attention：翻译模型里，目标语言单词去读源语言整句（K/V 来自 Encoder，不受因果限制）
  • 纯 GPT 没有 Encoder，所以删掉 Cross-Attention，只留 Masked Self-Attn + MLP

5.4 FNN / CNN / RNN 与 Transformer 的动机

网络 核心 适合 硬伤
FNN（MLP） 全连接、单向 表格、独立向量 不懂空间、不懂顺序；图片参数爆炸
CNN 小窗口滑动、参数共享 图像、网格 感受野靠堆层扩大，远距离弱；无时序记忆
RNN 循环隐藏态 h_t = f(x_t, h_{t-1}) 文本、语音、时序 串行，无法并行；长距离梯度消失

RNN 的致命点是”排队读句子”：必须等 h_{t-1} 算完才能算 h_t，长序列上既慢又容易遗忘（所以才有 LSTM/GRU 的门控）。

Transformer 的动机：让所有 token 一步之内直接互相看，既建立全局关联，又能整句并行。代价是——它天生不认顺序。这就引出了位置编码。

第六部分　正弦位置编码

6.1 为什么必须加入位置信息

自注意力对输入是置换等变的：把一句话里的词打乱，只要对应地把 Q/K/V 的行换一下，输出也只是换行，每个 token 算出来的东西完全一样。

换句话说：I love cat 和 cat love I，在没有位置信息时，注意力看到的是同一个集合、同样的两两相似度。语序信息必须由外部注入。

6.2 位置编码公式与符号说明

三个符号必须分清：

符号 是什么 对应矩阵的
pos token 在句子里的位置序号 0,1,2,3… 行号
2i / 2i+1 位置向量内部的维度下标（列号） 列号
i 分组编号（每一对 sin/cos 共用一个 i） —

6.3 i 的含义

i 不是位置，是”频率组的编号”。

向量是按两个分量一组打包的：第 2i 列放 sin，第 2i+1 列放 cos，这一对共用同一个 i 和同一个频率。

d_model = 4 时：

i 列 函数 分母
0 2i = 0 sin 10000^(0/4) = 1
0 2i+1 = 1 cos 10000^(0/4) = 1
1 2i = 2 sin 10000^(2/4) = 100
1 2i+1 = 3 cos 10000^(2/4) = 100

d_model = 8 时就有 4 组：i=0→列0,1；i=1→列2,3；i=2→列4,5；i=3→列6,7。

所以哪怕 pos=0，不管 i 是几，sin(0)=0、cos(0)=1，整行 PE 都是 [0,1,0,1,...]。

6.5 频率快慢的物理含义

  • i 小（靠前的列）：2i/d 小 → 分母接近 1 → θ_i 大 → pos 每 +1，角度跳一大截 → 转得快（高频） → 对相邻位置极敏感，负责分辨 pos=0 和 pos=1
  • i 大（靠后的列）：2i/d 大 → 分母巨大 → θ_i 极小 → pos 加 1 只挪一丁点 → 转得慢（低频） → 要隔几十上百位才看得出变化，负责长距离

比喻：高频组 = 秒表，低频组 = 年历。多组不同频率叠加，相当于给每个 pos 生成一个独一无二的”频率指纹”，整条 PE 向量几乎不会撞。

每个 i 就是一块独立表盘，指针角度 φ = pos · θ_i，指针坐标 (sin φ, cos φ) 落在单位圆上。

6.6 图注中关于位置编码奇偶位置说法的错误辨析

某教材图注写：

“pos 为 token 在句子中的位置，2i 和 2i+1 则是指示了 token 是奇数位置还是偶数位置，对于奇数位置的 token 和偶数位置的 token，Transformer 采用了不同的函数进行编码。”

这句是错的。它把”向量内部的维度下标”说成了”token 在句子里的位置”。

证据链（由强到弱）：

证据 1｜原论文《Attention Is All You Need》(2017)

“where pos is the position and i is the dimension. That is, each dimension of the positional encoding corresponds to a sinusoid.”

配套伪代码：

0::2 / 1::2 是列切片，不是对行（token）按奇偶分组。论文从没说过”奇数位置单词用 cos”。

证据 2｜TensorFlow 官方 Transformer 教程：pos 是序列位置，2i/2i+1 是 embedding 通道维度索引，沿通道交替 sin/cos。

证据 3｜IBM positional encoding 词条：k 是词在句子中的位置，i 是 embedding 向量维度索引，2i 是向量内偶数维、2i+1 是向量内奇数维。

证据 4｜The Illustrated Transformer（Jay Alammar）

证据 5｜反证（用图自己的数字）

正确 vs 错误：

正确 图注的错误理解
交替方向 沿**向量的维度（列）**交替 sin/cos 沿**序列的 token（行）**分 sin/cos

注意：公式是对的、矩阵相加的算术是对的，只有那一句中文解释是错的。 不用把整张图否掉。

第七部分　旋转性质：为什么必须 sin/cos 成对

7.1 Q11 解答：和角公式 → 旋转矩阵

对固定的一组 i，设角度 θ = pos·θ_i，往后挪 k 位角度增加 Δ = k·θ_i（Δ 只由 k 和 i 决定，和 pos 无关）。

中学和角公式：

把 (sinθ, cosθ) 当成一个二维向量的两个分量，写成矩阵乘法：

右边这个矩阵只和 Δ（也就是只和间隔 k）有关，和 pos 本身无关。

翻译成大白话：只要我手上存着 pos 位置的这一对 (sinθ, cosθ)，乘上一个只由 k 决定的固定矩阵，就得到 pos+k 位置的那一对数。

几何上：把一个落在单位圆上的点，绕原点旋转一个固定角度 Δ。这就是”旋转性质”。

小验证：Δ = π/2，cosΔ=0, sinΔ=1，矩阵 = [[0,1],[-1,0]]，θ=0 时向量 [0,1] → [1,0] = [sin(π/2), cos(π/2)] ✓

7.2 只留一个 cos 会坏在哪

假设每个位置只存 c = cosθ。想算 cos(θ+Δ)：

单个数字不足以完成旋转。 从几何看更直观：cosθ = 0.5403 对应单位圆上两个点（θ ≈ 1 或 θ ≈ -1），它们的 cos 相同，但旋转之后去往完全不同的地方。你分不清是哪一个，就不存在一个唯一的固定线性变换。

一对 (sinθ, cosθ) = 平面上完整定位一个点；单个 cos = 只知道横坐标，丢了相位的另一半。

7.3 在 I like to code 上逐位验证

d_model=4，两组：

  • i=0：θ_0 = 1/10000^0 = 1，每挪 1 位角度 +1
  • i=1：θ_1 = 1/10000^(2/4) = 1/100，每挪 1 位角度 +0.01

从 I(pos=0) 到 like(pos=1)，k=1

i=0 组：v_0 = [sin0, cos0] = [0, 1]

i=1 组：u_0 = [0, 1]，R_1 = [[cos0.01, sin0.01], [-sin0.01, cos0.01]]

从 like(pos=1) 到 to(pos=2)，k 仍然是 1 → 用同一个 R_0、同一个 R_1

再到 code，还是这两个矩阵。

规律：I→like、like→to、to→code 三对，间隔都是 1，用的完全是同一个变换矩阵。模型只需要学会”间隔 1”这一套，全句通用。

如果直接跳 k=2（I → to），用 k=2 对应的矩阵一步到位，不用中转。

注意：整个 4 维 PE 不是一次四维旋转，而是两套独立的二维单位圆各自旋转。 i=0 转得快（每步 1 弧度，四个词差别巨大），i=1 转得极慢（每步 0.01 弧度，相邻词几乎重合）——这就是”高频管近处、低频管远处”的直观样子。

7.4 「偏移」是不是意味着可以从 pos=0 递推出整条序列

数学上：是的。

给定起点，反复乘同一个旋转矩阵就能生成整条序列，不必对每个 pos 单独算 sin/cos。

但有两个”但是”：

  1. 工程上不会这么写。 实现里依然是循环直接算 sin/cos，因为矩阵连乘会有浮点误差累积。这个性质不是给程序员的计算捷径，是给模型的归纳偏置。
  2. 前提是成对 (sin, cos)。 只留一个 cos，递推链直接断掉。

7.5 那它的价值到底是什么

不管这段序列从 pos=0 开始还是从 pos=100 开始，只要两个 token 相差 k，它们之间就是同一种旋转关系。

为什么这很重要：注意力真正关心的往往不是”token A 在位置 5、token B 在位置 9”，而是”它们隔了 4 个“。

  • I(0) ↔ like(1)：k=1
  • to(2) ↔ code(3)：k=1

这两对的变换是同一个旋转。模型学”间隔为 k”只需学一次，可以复用到序列任何位置；如果没有这个性质，模型学到的是”pos0 配 pos1”、”pos2 配 pos3”这种绝对编号之间的映射，句子一长、出现训练没见过的 pos，立刻崩。

附带好处：外推。 训练最长 4 个词，推理遇到 pos=100、pos=101，三角函数公式照样能算出合法 PE，”间隔 k”的关系依然成立。对比之下，可学习位置编码（把 PE 当参数训练）超过训练长度就没有对应参数了。

第八部分　把旋转放进注意力打分：正弦 PE 的天花板

8.1 m、n 是什么

用句子 I(0), like(1), to(2), code(3)：

  • m = Query 的位置（当前正在算输出的是哪个 token）
  • n = Key 的位置（被拿来比对的 token）
  • q_m = “我（第 m 个词）要去找谁”
  • k_n = “第 n 个词对外展示我是什么样”

q_m · k_n 只是”一对”的分数，不是完整的注意力。 完整流程是：固定一个 m，遍历所有 n 算出一整排分数，softmax 成权重，再用权重对所有 v_n 加权求和：

一个 token 只有一组 q/k/v；但它会和每一个 k 各算一个分数，所以 m=1 时有 4 个 score。

8.2 内积的四项展开

原版流程：

因为 q_m = WQ·x_m + WQ·PE(m)、k_n = WK·x_n + WK·PE(n)，用 (a+b)·(c+d) = ac+ad+bc+bd 展开成四项：

四项的含义：

  1. 只比两个词本身语义像不像（完全不含位置）
  2. m 的语义 去匹配 n 的位置
  3. m 的位置 去匹配 n 的语义
  4. m 的位置 和 n 的位置的关系 ← 前面讲的旋转、距离 k，全部只属于这一项

8.3 第 4 项确实只依赖 k（严格推导）

把 PE 写成每组的 [sin(posθ_i), cos(posθ_i)]，第 4 项（先忽略 WQ、WK，即取 A = I）就是各组的内积之和：

结论：PE 和 PE 的点积精确等于 Σ_i cos(k·θ_i)，只含 k = n-m，m、n 各自彻底消失。

这比”差不多只和 k 有关”更硬：它是恒等式。也就是说，位置-位置这一项天然是平移不变的。

8.4 短板：第 4 项外面还有 WQ、WK，旁边还有交叉项

真实公式是 PE(m)ᵀ (WQᵀ WK) PE(n)。设 A = WQᵀ WK：

只有当 A 在每个二维块上恰好等于 c_i × 旋转矩阵（即和旋转可交换）时，这个式子才会化简成 Σ_i c_i cos(kθ_i)，才保持”只依赖 k”。

而 WQ、WK 是随机初始化、自己学出来的普通矩阵，几乎不可能满足这个条件。所以：

  • 第 4 项本身被 WQ、WK 包裹后，绝对位置 m、n 就渗进来了
  • 第 2、3 项是纯交叉项，把”单词语义”和”位置”绑在一起，会引入绝对位置干扰
  • 结果：整套 score 并不天然只依赖 k

具体到那两组 k=1 的配对（A: m=1,n=2；B: m=2,n=3）：

最里面那个 PE(1)ᵀPE(2) 和 PE(2)ᵀPE(3) 是相等的（都等于 Σcos(θ_i)），但 x_1、x_2、x_3 是不同的单词，交叉项不一样，最终位置贡献并不相等。

一句话总结原版：正弦 PE 自带”距离 k = 等价旋转”这个宝藏，但它被提前加到 embedding 上，经过 Q/K 投影矩阵和交叉项之后，这个干净的关系被污染了。模型得自己费劲从混杂信号里把相对距离分离出来——学习负担重、收敛慢、泛化差。

第九部分　RoPE：把旋转挪到 Q、K 上

9.1 改造点只有一句话

不再提前生成 PE 加到 embedding，而是等 Q、K 投影出来之后，直接对 Q、K 的二维子平面施加旋转，旋转角度由它的 pos 决定。V 不旋转。

分组规则、频率表 θ_i 都和正弦 PE 一模一样，只是”用法”变了：正弦 PE 是把表盘指针坐标存下来当向量分量；RoPE 是拿这个转速去旋转 Q/K 在这个表盘上的分量。

9.2 公式与推导

每组（第 2i、2i+1 分量）：

简写：q'_m = R(mθ_i) · q_m，对 k_n 做同类操作（角度用 n）。

利用旋转矩阵是正交矩阵：R(a)ᵀ = R(-a)（转置 = 反向旋转）。

m、n 消失了，只剩下差值 k = n-m。 而且整个过程没有任何”内容 × 位置”的交叉项——位置是通过旋转角度差注入的。

写成每组的分量形式更直观（二维块内，q=(a,b)、k=(c,d)、φ=(n-m)θ）：

右边两项里，(ac+bd) 和 (bc-ad) 都是纯语义量，位置只通过 φ = (n-m)θ 出现。

9.3 两组 k=1 的配对，在 RoPE 下

  • A：m=1, n=2 → (q'_1)ᵀ k'_2 = q_1ᵀ R(1·θ) k_2
  • B：m=2, n=3 → (q'_2)ᵀ k'_3 = q_2ᵀ R(1·θ) k_3

两组用来耦合位置的矩阵都是同一个 R(1·θ)。位置施加影响的方式是全局统一模板；两组分数的差异只来自单词本身语义（原始的 q、k），不再来自位置机制。

⚠️ 但要说清：这不代表两对的总分相等。q_1,k_2 和 q_2,k_3 语义不同，总分当然可以不同。区别在于：

正弦 PE RoPE
位置何时注入 和词 embedding 提前相加，语义+位置混在一起 语义先投影出 q/k，之后旋转注入
有无「语义×位置」交叉项 有，且是公式自带 没有
k=1 的两对 PE 内部满足旋转，但交叉项被单词和绝对位置污染 位置耦合矩阵固定为 R(θ)，平移无关
性质来源 只是 PE 向量单独的潜力，要模型自己学 代数化简直接保证，写死在打分公式里

9.4 三个直觉

① 钟表表盘
每组二维平面 = 一块表盘，pos 决定指针指向。算分数看的是两根指针的夹角，而不是各自指向几点。两个 token 同时往后挪 100，夹角不变 → 位置贡献不变。

② 长程衰减（long-term decay）
间隔 |k| 越大，旋转夹角越大，cos φ 整体上衰减，位置带来的耦合自然变弱。这符合语言规律（相邻词更容易互相影响），而且不需要额外加惩罚项。这是 RoPE 常被提到的经验性质，不是严格定理，但方向上成立。

③ 外推友好
角度是连续三角函数，pos 取任意大都能算出合法旋转矩阵。而可学习位置编码超出训练长度就没有参数。这是 Llama、Qwen 等主流模型全部选 RoPE 的根本原因。

9.5 RoPE 的代价（原文没展开，但必须知道）

  • 只旋转 Q、K，V 不动——因为位置只该影响”相似度”，不该影响”要搬运的内容”
  • 高频组在长序列上会”转太多圈”（角度超过 2π 后混叠），所以出现了 NTK-aware 插值、YaRN、位置插值等长上下文外推方案
  • θ_i 的基数是超参：原版 10000，Llama-3 提到 500000（也是为了长上下文）

10.2 mask 与 PE / RoPE 是正交的两件事

管什么
PE / RoPE 假如这一对 (m,n) 允许计算，位置怎么影响它的分数
掩码 mask 这一对 (m,n) 能不能参与计算

位置编码的数学完全不区分单向/双向。

对比：

  • (m=1, n=2)：k=+1，GPT 里被屏蔽
  • (m=2, n=1)：k=-1（往前看一位），GPT 允许，公式照常：

间隔是 -1，旋转矩阵换成 R(-θ)，数学完全一样，只是角度反向。

所以：k 可以是正（往后看，双向）、负（往前看，因果），也可以是 0（看自己）。RoPE 和正弦 PE 都能处理，符号只是让旋转方向反过来。
