基于Butterfly的网站美化教程05：油画卷轴跳转过渡

发表于2026-10-18|更新于2026-10-20|技术学习
|浏览量:

前言

上一篇做完 Music 播放器和 Movie 画廊之后，我看着自己的画一直有个手痒的念头：既然访客点进来看的是这些画，为什么不用画本身来做页面切换的遮罩？

于是做了这个：点击任意站内链接，一幅油画从屏幕顶部卷轴展开铺满全屏，画面中央淡入画名、作者与年代；PJAX 在完全遮住的那一瞬静默换页；随后卷轴向上收起，露出新页面。

整套东西没有引任何第三方库——没有 GSAP、没有 anime.js、连 View Transitions API 都没用（PJAX 自己管 DOM 交换，和原生 API 对不上）。纯 CSS 动画 + 一段调度 JS，加起来 590 行。

效果就是你现在点的每一个链接。5 幅画洗牌轮转，不会连着撞同一幅。

时序拆解

先看清楚它到底在干什么，后面所有设计选择都是为了这张图：

三个关键点：

  • 遮罩必须完全铺满时才能换页，否则会看见内容”啪”地跳一下；
  • 遮罩铺满 → 换页 → 收起这三段是解耦的。换页慢（网络差）就多停在铺满状态一会儿，绝不提前收起；
  • 收起用 ease-in 曲线（起步慢、末段快），读起来才像”布被抽走”，而不是”啪一下没了”。

整体架构

第一步：配图预处理

为什么不直接用原图

画廊那批原作是 148KB–780KB 不等，最宽也只有 1280px。直接拿来做全屏遮罩有两个问题：

  1. 重。一张 780KB 的图，只为了看 1 秒，而且每次跳转都可能用到。
  2. 比例不对。原作从 0.66（竖幅《撑阳伞的女人 1886》）到 3.01（横幅《睡莲·夕阳》）都有。遮罩要 background-size: cover 铺满任意视口，比例不统一就得运行时二次裁切——卷轴展开过程中画会持续”重新取景”，看着像在呼吸，很假。

所以离线一步到位：统一裁成 16:9，运行时 cover 就再也不会裁切。

为什么还要分两档

遮罩是全屏元素。手机竖屏（390×844）铺一张 1280×720 的图，等于把 210KB 的数据放大到远超屏幕的需求，纯浪费。所以：

档位 尺寸 质量 体积
-1280 1280×720 q76 20–350KB
-640 640×360 q66 2–65KB

JS 侧按 matchMedia('(max-width: 768px)') 选档。

裁切焦点

裁成 16:9 对宽画是切上下，对高画是切左右。切哪一段不能靠居中——《星夜》居中会削掉下半截的村庄和柏树根部，画面重心就散了。所以每幅配一个 focus：

focus 是裁切窗口的垂直中心（0 = 贴顶，0.5 = 居中，1 = 贴底）。

永不放大

这条是踩过坑的。最初我把桌面档定成 1600px，结果 PIL 老老实实把 1280px 的图放大到 1600——不增加任何细节，体积还翻了近一倍，还更糊。

第三步：卷轴动画

用 clip-path，不用 scaleY

直觉写法是让布 transform: scaleY(0 → 1)。错——scaleY 会把画纵向压扁再拉回来，整个展开过程画都在变形。

正确做法是固定大小的画 + 移动的裁剪窗口：

clip-path 不参与布局、也不改变 background-size 的计算基准，所以画从头到尾都是满屏 cover 的原样，只有可见区域在变。

踩坑：五个真实的 bug

这部分可能比上面的实现更有价值。每一个都是先写完、看起来对、实际翻车才改对的。

坑 1：图片被放大

现象：桌面档定的 1600px，生成出来 322–482KB，比原图还大。

原因：原作最宽 1280px，PIL 照着 1600 拉伸了。放大不增加任何细节，只增加体积。

修复：加一句永不放大。1280 档从 349KB 降到 210KB。

坑 2：收起动画被重放两遍

现象：时间线采样出来，底轴在屏幕底边卡了 114ms 才动。

原因：

这两个事件会连着触发。第二次 hide() 里 clearTimeout(revealTimer) 之后又 setTimeout 了一遍，导致 st-rolling 刚启动就被移除再重加，动画从头再来。

修复：加个 revealing 标志。

坑 3：快速跳转时画名根本不出现

现象：本地测（秒开）画只展开 40% 就开始收，中央的画名一次都没显示。

原因：原本的逻辑是

即”至少停留 180ms”。但缓存命中时 pjax:complete 2ms 就返回了，180ms 远小于展开所需的 420ms——布才铺到 40% 就被折回去。而画名是 200ms 才淡入的，于是永远等不到。

修复：不跟 CSS 时长硬对齐，改成等 animationend。

coverReadyAt 是从动画真正跑完开始算的，所以以后想把 CSS 里的 340ms 改成 500ms，JS 不用跟着改。

兜底也留了：万一 transition.css 没加载、animationend 永远不来，MAX_COVER_MS（2.5s）会强制收场，不会把页面锁死。

坑 4：移动端底轴跑偏

现象：手机上看，底轴到达的位置比画布下沿低了一截。

原因：行程用了 window.innerHeight。

但遮罩是 position: fixed; inset: 0，只认视觉视口。移动端地址栏收起/展开时，视觉视口和 innerHeight 会对不上。

修复：直接量遮罩自己的高度，并额外监听 visualViewport：

坑 5：金杆永久滞留页面顶端

这个是用户发现的，也是最隐蔽的一个。

现象：跳完一个页面之后，屏幕最顶部永久杵着一根金色的卷轴杆，压在站点 header 上，整个会话都在。

根因：看 DOM 层级——

两根卷轴杆是 .st-sheet 的兄弟节点，不受它的 clip-path 裁剪。 而 .st-roller 的基态是：

动画收尾时 class 被摘干净，两根杆回到基态——top: 0、opacity: 1、z-index: 9500——直接压在页面顶上。

再加上遮罩是懒创建的，于是表现得很诡异：首次跳转前没有这根杆，点过一次之后永久存在。

修复：把可见性彻底交给动画管，基态负责隐藏。

但这样一来，四个 keyframes 必须各自显式声明 opacity，否则基态的 0 会盖住动画，卷轴杆整个不出现：

特别注意 st-rod-up 末帧的 opacity: 0 不能省：底轴要一路升到 -140% 出画，但收起用的是 cubic-bezier(0.5, 0, 0.75, 0)——极端 ease-in，起手 150ms 它几乎还停在屏幕底边，光靠位移根本来不及在收起结束前离开视野。

收起时的”画框感”

还有一处是用户看出来的设计缺陷，不是 bug 但值得记一笔。

最初顶轴收起时是”向上滑出”的，用的曲线和底轴一样是 cubic-bezier(0.5, 0, 0.75, 0)。结果按上面的表，起手 150ms 两根杆几乎都还杵在原位，中间夹着一条画——读起来就是一个画框，而且横在正在揭晓的新内容上面。

改法很简单：收起时顶轴原地淡出（120ms），不再位移。

顺带发现顶部那条压边暗带也会变成横条——因为它挂在 .st-sheet 里，而 sheet 的上沿在 clip-path 收起过程中始终不动，所以那条暗带全程钉在屏幕顶端。于是把它拆成独立一层，跟着一起淡出（200ms，比杆稍慢，像阴影”落下去”而不是被剪掉）：

底边那条压边保留——收起时它正好压在布的退场上，能强化边缘感。

展开和铺满停留时的挂轴观感是故意保留的。所以你会看到”铺满时有轴、收起时没轴”这个变化。这是个取舍：挂轴是”看画”的氛围，横条框住正在揭晓的新内容则是噪音。

构建与部署

⚠️ 主题仓库必须一起推

本站的 themes/butterfly 是独立 git 仓库（分支 custom），而 CI 是从 GitHub 重新 clone 主题来构建的：

custom 分支原本没有 upstream，第一次推需要 -u。

常见问题

问题 原因 & 解决
线上没有动画，JS 404 主题仓库没推。CI 从 GitHub clone custom 分支，不是本地目录
改了样式没生效 浏览器缓存。bump _config.butterfly.yml 里的 ?v=
画只展开一半就收回去 MIN_COVER_MS 机制被破坏。确认 st-unroll 的 animationend 能触发
卷轴杆整个不出现 四个 keyframes 忘了写 opacity，被基态 opacity: 0 盖住
页面顶端一直有金杆 .st-roller 基态没设 opacity: 0，或它被放在了 .st-sheet 外面
手机上底轴位置不对 行程用了 innerHeight。改成量遮罩自身 clientHeight，并监听 visualViewport
收起时看着像画框 顶轴用位移收起。正解是收起时原地淡出
画被拉伸变形 用了 scaleY。改成固定画布 + clip-path: inset()
配图太大 桌面档宽度超过了原图宽度，PIL 放大了。加一句尺寸兜底

总结

  • 遮罩 = 固定画布 + clip-path 裁剪，不是 scaleY。用 clip-path 是为了不破坏 background-size: cover 的计算基准
  • 配图离线一次成型：统一 16:9、分 1280/640 两档、永不放大、每幅配裁切焦点
  • PJAX 浮层挂 body：主题替换的是 #body-wrap 等区域，body 不在其中
  • 别跟 CSS 时长硬对齐：驻留时间从 animationend 推算，改 CSS 不用改 JS
  • 可见性基态必须显式隐藏：尤其是不受父级 clip-path 裁剪的兄弟节点
  • 验证要测静止态，不只是动画进行中

以及最后一条，来自实际踩坑：

ease-in 曲线会让元素在动画前段几乎不动。 如果那个元素”停下来等”的状态读起来有歧义（这里读成了画框），就该在它停留期间就淡出，而不是指望位移能赶上。

完整源码：Y3148y/hexo-theme-butterfly 的 source/css/transition.css 与 source/js/paint-scroll-transition.js，裁图脚本在主仓库 tools/build-transition-art.py。
