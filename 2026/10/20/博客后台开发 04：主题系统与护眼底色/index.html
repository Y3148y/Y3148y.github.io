从「白色刺眼」说起

上一篇讲完部署和 CI，后台的骨架算是齐了。这一篇回到界面上——因为我每天盯着它写文章，发现一个很实际的问题：白色面板盯久了刺眼。

最初后台只有一套配色：浅灰底、白面板、深字。晚上写文章的时候，尤其是房间灯关了只剩屏幕亮着，那片白是真的晃眼。深色模式后来加了，但深色模式下我还要看图片预览，不是所有场景都适合。

于是我想要的效果是这样的：

  • 深色 / 亮色照旧，跟随系统，也能手动锁死；
  • 再来一档护眼底色——经典的豆沙绿那种，整个界面沉在一片低饱和的绿里；
  • 护眼的深浅可调，因为「多深的绿」这件事只有眼睛说了算，拖一下滑杆就行。

做下来一共踩了三个值得记录的坑：主题档位怎么组织、系统暗色怎么会把护眼色盖掉、以及滑杆那个「正中就是原色」的锚点是怎么反解出来的。

坑一：系统暗色把豆沙绿盖掉了

做完豆沙绿我顺手切了系统深色模式测试，结果护眼档整个变暗了。

现象

当时的暗色跟随逻辑是这样写的：

意思是「系统暗色时，除非用户强制了亮色，否则走暗色」。当时只有三档，这么写没问题。加了 green 之后，用户选了豆沙绿，data-theme="green"——它不是 light，:not() 不排除它，系统一暗，这条规则就把它盖回暗色了。

为什么它会赢

两个选择器的特异性对比：

  • [data-theme="green"] —— 0,1,0（一个属性）
  • :root:not([data-theme="light"]) —— 0,2,0（:root 是伪类，:not() 里的参数也计入）

后者更高，无论顺序怎么排都是它赢。排除法的本质是白名单的补集——档位从一个变成六个以后，补集的语义就不对了：我真正想表达的是「没有选择时才跟随系统」，而不是「不是亮色就跟随系统」。

修法：白名单

:not([data-theme]) 只在根元素上没有这个属性时命中——也就是「跟随系统」这一档。强制暗色走自己的 [data-theme="dark"] 分支，护眼三档和强制亮一样天然不落进这条规则。以后再加新的亮色系档位，零维护。

滑杆：其实是 color-mix 在干活

「多深的绿」是主观感受，我不想手调三次色值让用户挑，直接给滑杆。

如果滑杆直接改 --bg 的值，JS 就得知道每个档位的色板——耦合死了。更好的办法是把「基准色」和「深浅」拆开：深浅统一用一个「混白率」变量表达，由 color-mix() 现场算色：

color-mix(in srgb, A, B p%) 的结果是 A×(1−p) + B×p——白率 50% 就是基准色和纯白各占一半。--theme-mix 从 0%（基准色，最深）到 100%（纯白），滑杆拖的是它，全部档位共用一个变量：

行内样式设置的变量优先级高于样式表，所以滑杆拖动立即生效，不用刷新、不用重新计算任何档位。

两个细节：

双声明兜底。color-mix() 需要 Chrome/Edge 111+（2023 年初）。每个变量先写一行纯色再写 color-mix，老浏览器解析不了第二行就自动用第一行，界面退化为固定原色，不炸版。

兜底色和基准色不同。兜底行写的是用户会看到的原色（#c7edcc），color-mix 里的 #8fdb99 是反解出来的基准深色——下一节讲它为什么长这样。

锚点反解：让滑杆正中精确命中原色

这是整个功能里我最满意的一步。

滑杆有个体验问题：缺省位置停在哪？ 如果基准色随便选一个深绿，那缺省混白率就得配一个凑出来的百分比，凑出来的数永远不是精确值——舍入误差会让「缺省色」和「我最初定稿的豆沙绿」差上一两个色阶，眼睛不一定看得出，但我自己知道。

我想要的是：滑杆拉到正中（50%），颜色精确等于第一版定稿的那套。

反解

color-mix 是逐通道线性插值：

target（原色）和 r₀（锚点白率）已知，反解基准色：

r₀ 取 50% 有个额外好处：分母是 0.5，等于 base = 2 × target − 255，逐通道都是整数，零舍入误差。

拿豆沙绿验证一遍。原色 #c7edcc = RGB(199, 237, 204)：

通道 反解 基准色
R 199 × 2 − 255 = 143 143
G 237 × 2 − 255 = 219 219
B 204 × 2 − 255 = 153 153

基准色 #8fdb99。再正向混一遍：143×0.5 + 255×0.5 = 199、219×0.5 + 127.5 = 237、153×0.5 + 127.5 = 204——精确回到 #c7edcc，一个色阶都不差。

三个护眼档、九个变量（底色、面板、代码底各三档）全部这样解出来：

档 原色（50%） 深端（0%） 面板原色 → 深端
豆沙绿 #c7edcc #8fdb99 #e8f4eb → #d1e9d7
米黄 #faf9de #f5f3bd #fcfaec → #f9f5d9
青灰 #e2eae8 #c5d5d1 #f0f4f3 → #e1e9e7

滑杆两端都有满行程：往左比原色更深，往右更浅，正中就是定稿色。「默认」从此不再是一个被硬凑出来的值，而是坐标系的原点。

恢复默认：勾选框与「无值即缺省」

滑杆拖乱了的用户需要一个一键回家的按钮。我加了一个「恢复默认」勾选框：

  • 勾上：删掉 admin.theme.mix 这个键 + 滑杆回到 50 并 disabled 锁死；
  • 取消：解锁，可以继续拖。

为什么不勾上时写入 50 而要移除这个键？因为「无值 = 缺省」是一层数据语义：缺省值只存在于代码里（--theme-mix, 50%）。哪天我把默认深浅调了，已勾选「恢复默认」的用户自动跟着新缺省走，不需要迁移任何旧数据。勾选状态自己单独存一个键，打开设置时复显。

防闪白：首帧之前就要定颜色

整个主题系统还有一个共同的敌人：闪白。

样式表加载后 data-theme 还没设置，页面会先用默认亮色渲染一帧，再跳成深色/护眼色——晚上用的时候这一下非常扎眼。解法是在 <head> 里塞一段阻塞式内联脚本，在首帧渲染之前就把属性和变量设好：

收尾

全部做完，无头 Chrome 的回归脚本扩到 60 条断言全绿：六个档位的属性与背景计算值逐一核对、滑杆拉到深端核对精确色值（rgb(143, 219, 153)，就是那个反解出来的 #8fdb99）、模拟系统暗色确认护眼档不被覆盖、勾选锁定与解锁、刷新后状态保持。

现在的效果：整片界面沉在豆沙绿里，写久了眼睛不紧绷；想深一点浅一点，滑杆拖一下；拖乱了，勾一下「恢复默认」回到定稿色。

技术上整个功能没有一行第三方代码，靠的是三件老东西的组合：CSS 变量（数据与表现分离）、color-mix()（把「深浅」从颜色里拆成独立维度）、行内样式变量（JS 与样式表之间最低成本的通道）。唯一有点「数学」的部分——锚点反解——也只是中学代数，但它让「默认值」从凑数变成了精确值，我认为这是整个功能里最值得复用的一招。
