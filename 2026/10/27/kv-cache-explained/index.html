KV Cache详解

发表于2026-10-27|更新于2026-10-27|技术学习

KV Cache

一、q、k、v 分别是什么

大模型自回归生成时，每一轮都会为新的 token 生成新的 k、v、q，历史的 k、v 直接复用，而 q 本轮用完即丢。

在 Transformer 的注意力机制里，每个 token 的隐状态会经过三组不同的线性投影，得到三个向量 q、k、v：

  • q（Query，查询）：当前 token「想找什么信息」，用来和历史的 k 做匹配打分。
  • k（Key，键）：每个 token「能提供什么信息的索引」，被后续 token 的 q 检索。
  • v（Value，值）：每个 token「实际携带的内容」，按注意力权重加权求和后输出。

用一句话概括：q 是提问，k 是目录，v 是正文。注意力分数 softmax(q·kᵀ/√d) 决定从每个 v 里取多少内容。

二、q、k、v 是怎么得到的

q、k、v 三者是同一套流程：当前 token 的隐状态分别乘上三组不同的权重矩阵，就得到三个向量，区别只在于用的是哪一组权重。

设第 t 步新 token 的隐状态为 x_t（维度 d_model），三组投影矩阵分别为 W_q、W_k、W_v（形状 d_model × d_head），则：

几点需要注意：

  • 来源是同一个隐状态：q、k、v 都来自同一个 x_t，只是乘了不同的权重矩阵，所以三者维度可以不同（多头场景下按头切分）。
  • 多头注意力里按头拆分：W_q 通常一次投影出 n_heads × d_head 维，再 reshape 成多个头，每个头各自算 softmax(q·kᵀ/√d_head)，最后拼接再过一个输出投影 W_o。
  • q 只算当前 token：decode 阶段每步只对最新 token 做一次 x_t · W_q，得到 1 个 q；而 k、v 虽然也是每步只算新的一个，但算完要追加进缓存供后续复用。
  • 位置信息在投影之后注入：RoPE 之类的方案是在 q、k 投影之后对它们做旋转，而不是改变 q 的生成方式。所以「q、k、v 是怎么得到的」可以一句话回答：当前 token 的隐状态分别乘上 W_q、W_k、W_v 三个投影矩阵，再按头拆分，就得到了这一步要用的 q、k、v。三者的区别只在于权重矩阵不同、后续用途不同：q 用来提问，k 用来被检索，v 用来被加权取内容。

三、为什么只缓存 k、v，不缓存 q

关键在于自回归生成的计算方式：第 t 步时，当前这个 token 的 q、k、v 是一起算出来的，但算完之后命运不同——q 只在这一步和「前面所有 token 的 k、v，以及刚刚生成的k、v」做注意力，用完即丢；k、v 则要追加进缓存，供后面每一步复用。

这里要澄清一个常见误解：q 和历史的 k、v 做完注意力，并不能直接「生成 token」。注意力只是 Transformer 一层里的一个子步骤，它算出的只是当前 token 在这一层的表示；这个表示还要经过前馈网络、残差，逐层往上传递，最后由 lm_head 映射成词表概率分布，(logits)采样后才得到下一个 token。

所以顺序是「先有输入 token → 再算 q、k、v → 再做注意力 → 最后预测下一个 token」，而不是「先生成 token，再补算它的 k、v」。第 t 步的输入是第 t-1 步的输出，第 t 步的输出又是第 t+1 步的输入。

拿「北京天气怎么样？」→「北京天气很好」走一遍：

  • 每步只输出一个新 token：界面上的「北京天气很好」就是这 4 步各吐 1 个 token 拼起来的。
  • 上一步的输出立刻变成下一步的输入：不喂回去，模型就没有依据预测下一个词。
  • prompt 只做输入：prefill 阶段一次性并行处理，k、v 全部写进缓存供后续复用。

回到「为什么只缓存 k、v」本身，还有三点要强调：

  • k、v 会被反复使用：第 t 步算出的 k、v 追加进缓存后，第 t+1、t+2……步仍要拿历史所有 token 的 k、v 参与注意力。不缓存就得把整段前缀重跑一遍，复杂度从 O(n) 变成 O(n²)。
  • q 只用一次：某个 token 的 q 只在它自己这一步参与打分，算完就再也不需要，缓存纯属浪费显存。
  • 注意区分「算」和「存」：每步都要算当前 token 的 q、k、v，区别只在于 q 算完就丢、k、v 算完要存。「只缓存 k、v」说的是存什么，不是「只算 q」。

缓存是「只增不改」的：每步只把新算出的 k_t、v_t 追加到末尾，旧的原封不动，写入量是 O(1) 而不是 O(n)。

四、KV Cache 的优化方案：MQA、GQA、MLA、CSA、HCA

0. 先厘清「多头」到底指什么

很多人的困惑来自一个误解：以为「多头」是把 token 的隐状态按维度切成几段，每段算一个头。不是这样。 多头是做多组独立的线性投影，每个头看到的都是完整的 x_t，只是用的投影矩阵不同；在标准 MHA 里，每个头确实有自己独立的 k、v。那为什么 MQA / GQA 还能「共享」k、v？关键在于：共享的不是「同一个头内部的 k、v」，而是「让多个 q 头去查同一份 k、v」。

  • MQA：只保留一组 W_k、W_v，所有 q 头共用这一份 k、v。相当于「4 个人问问题，但只有一本目录、一本正文」。
  • GQA：保留 g 组 W_k、W_v，把 q 头分组，组内共用一份 k、v。相当于「4 个人分成 2 组，每组共用一本目录」。
  • 共享的代价：不同 q 头本来可以检索不同子空间的信息，现在被迫看同一份 k、v，表达能力下降，所以效果会略逊于 MHA——这正是 MQA/GQA 用「少量效果」换「大量显存」的本质。

一句话总结：多头 = 多组投影、多个并列的注意力子空间；每个头在 MHA 里确实有独立的 k、v；MQA/GQA 的「共享」是主动放弃这种独立性，让多个 q 头复用同一份 k、v 投影，从而把缓存从 n_heads 份降到 1 份或 g 份。

从缓存份数看：MHA 需要 n_heads 份 k、v，MQA 只需 1 份，GQA 需要 g 份（图中 4 个 q 头时分别是 4 份、1 份、2 份）。q 头数量三者相同，差别只在于有多少个 q 头去共享同一份 k、v——共享得越彻底，KV Cache 越小，但每个 q 头能检索的信息子空间也越受限。

上面已经厘清了「多头」与「共享 k、v」的关系，接下来按「减少头数 → 压缩表示 → 稀疏/分层」的思路，逐一介绍各类优化方案。它们本质上都在回答同一个问题：如何在不损失（或少损失）效果的前提下，把 KV Cache 占用的显存和带宽降下来。

1. MHA（Multi-Head Attention）：基准方案

在讲各种优化之前，先把「基准」说清楚。MHA 就是标准的多头注意力：n_heads 个 q 头，每个头都有自己独立的一组 W_q^i、W_k^i、W_v^i，因此每个头都有独立的 k、v。

  • 缓存规模：k、v 各 n_heads 份，是后面所有方案的比较基准。
  • 特点：表达能力最强，各头可以关注不同的子空间（语法、位置、语义等）。
  • 问题：长上下文时 KV Cache 显存占用最大，推理带宽压力也最大。

2. MQA（Multi-Query Attention，多查询注意力）

MQA 的做法是：所有 q 头共享同一份 k、v，只保留多份 q。

  • 缓存变化：k、v 的头数从 n_heads 降为 1，KV Cache 直接缩小到原来的 1 / n_heads。
  • 代价：表达能力下降，训练稳定性变差，效果通常略逊于 MHA。
  • 适用：对推理速度、显存极度敏感的场景，是后续 GQA 的基础。
  • 代表：PaLM、Falcon 等模型采用过。

3. GQA（Grouped-Query Attention，分组查询注意力）

GQA 是 MHA 与 MQA 的折中：把 n_heads 个 q 头分成 g 组，每组共享一份 k、v。

  • 缓存变化：k、v 头数为 g，缓存缩小到 g / n_heads。当 g = n_heads 退化为 MHA，g = 1 退化为 MQA。
  • 优势：在效果接近 MHA 的同时大幅降低缓存，是当前主流大模型（如 Llama 2/3 系列）的默认选择。
  • 一句话记忆：GQA = 分组共享 k、v，用少量效果换大量显存。

4. MLA（Multi-head Latent Attention，多头潜在注意力）

MQA / GQA 是「少存几份 k、v」，MLA 则是「把 k、v 压缩成一个低维隐向量再存」。

  • 核心思路：不直接缓存完整的 k、v，而是缓存一个低秩的 latent 向量（压缩表示），推理时再通过上投影还原出 k、v。
  • 缓存变化：缓存维度从 n_heads × d_head 降到 latent 维度，压缩比可以做到数倍甚至十倍以上。
  • 代价：多了一次投影计算，实现更复杂；需要与 RoPE 等位置编码方案配合处理（DeepSeek 的做法是额外携带一小段解耦的 RoPE 维度）。
  • 代表：DeepSeek 系列采用的 MLA，在长上下文场景下显存优势明显。

5. CSA（Chunked / Compressed Sparse Attention，分块压缩稀疏注意力）

CSA 属于「结构/稀疏」层面的缓存优化思路，常见于长上下文与稀疏注意力相关工作中。

  • 核心思路：把序列切块，对块内 k、v 做压缩或稀疏选择，只保留对当前 q 真正重要的部分参与注意力。
  • 效果：让缓存随序列增长得更慢，同时把注意力计算量从「全量两两比较」降下来。
  • 代价：分块粒度、选择策略需要调参，可能损失部分细粒度信息。

6. HCA（Hierarchical / Hybrid Cache Attention，分层混合缓存注意力）

HCA 同样属于结构层面的思路，重点在「分层」与「混合」。

  • 核心思路：对缓存做分层或混合管理，近期 token 保留完整 k、v，久远 token 用压缩表示或摘要替代。
  • 效果：兼顾局部精度与长程信息，避免滑动窗口那样「一刀切」地丢掉远距离内容。
  • 代价：结构复杂，需要设计分层策略与压缩方式。

说明：CSA、HCA 在不同论文/实现中命名与细节并不完全统一，这里给出的是它们共同的设计取向——通过分块、压缩、分层来减少需要完整保留的 k、v 数量，具体公式与实现请以对应论文为准。

7. 其他工程手段

  • PagedAttention：像操作系统管理内存分页一样管理 KV Cache，按块分配、按需增长，显著减少显存碎片，提升 batch 吞吐（vLLM 的核心技术）。
  • 量化压缩：把缓存从 FP16 压到 INT8 / FP8 甚至更低，直接按比例减少显存占用，需注意精度损失。
  • 滑动窗口 / 稀疏丢弃：只保留最近 w 个 token 的 k、v（如 Mistral 的滑动窗口注意力），或按重要性丢弃过远的历史，把缓存从线性增长变为常数上界。

8. 方案对比

方案 核心做法 缓存缩减 主要代价
MHA 每头独立 k、v 基准 缓存最大
MQA 所有头共享 1 份 k、v 约 1/n_heads 效果下降
GQA 分组共享 k、v 约 g/n_heads 轻微效果损失
MLA 缓存低秩 latent 再还原 数倍以上 实现复杂、多一次投影
CSA 分块压缩、稀疏选择 随设计而定 结构复杂、需调参
HCA 分层混合管理缓存 随设计而定 结构复杂、需调参
PagedAttention 分页管理缓存 减少碎片 需配套推理框架（vLLM）
量化 降低缓存精度 按位宽比例 精度损失
滑动窗口 只留最近 w 个 常数上界 丢失长程信息

选型建议：训练新模型优先考虑 GQA（成熟、生态好）；追求极致长上下文可评估 MLA；推理部署阶段叠加 PagedAttention + 量化通常收益最直接；滑动窗口适合对长程依赖要求不高的场景。

追问：k、v 都共享成一份了，那和单头还有什么区别？

这是最容易卡住的一个点：既然 MQA 里所有 q 头都查同一份 k、v，那不就退化成单头注意力了吗？不是。 关键在于「共享 k、v」和「单头」是两件不同的事：

  • q 仍然是多份的，而且各不相同。MQA 里第 i 个头依然有自己的 W_q^i，q_i = x_t · W_q^i，不同头的 q 落在不同的子空间里。它们只是去查同一份 k、v，但「问的问题」不一样，算出来的注意力权重 softmax(q_i·kᵀ/√d) 也各不相同，最后加权求和得到的 out_i 自然不同。
  • 单头是「只有一份 q、一份 k、一份 v」。单头注意力只有一个 W_q、一个 W_k、一个 W_v，只产生一组注意力权重、一个输出向量。MQA 有 n_heads 组 q、n_heads 组注意力权重、n_heads 个输出向量，只是它们共用同一份被检索的 k、v。
  • 输出投影 W_o 的输入维度也不同。MHA/MQA 的 W_o 输入是 n_heads × d_head = d_model，拼接的是 n_heads 个头的输出；单头的输出投影输入只有 d_head。多头结构带来的「多个子空间并行、再拼接融合」这一步，MQA 完整保留了。

用一句话概括：MQA 共享的是「被查的目录和正文」（k、v），没有共享「提问的方式」（q）。所以它仍然是多头注意力，只是把「每个头各备一份 k、v」改成了「所有头共用一份 k、v」。

那为什么共享 k、v 会掉效果？因为不同 q 头原本可以检索不同的 k、v 子空间——比如一个头关注语法、一个头关注指代，各自有专属的「目录」。共享之后，所有头只能在同一份目录里找，检索的多样性被压缩了，表达能力自然弱于 MHA。但注意：掉的是「检索目标的多样性」，不是「头的数量」。q 头该有几个还是几个，注意力的并行子空间一个没少。

从这张对照能看出：MQA 与单头的差别在「q 和输出都是 4 份」，与 MHA 的差别只在「k、v 从 4 份变成 1 份」。所以 MQA 是「多头 + 共享 k、v」，而不是「退化成单头」。
